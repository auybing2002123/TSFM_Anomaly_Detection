# TSFM Anomaly Detection 实验结果总表

## 指标说明

| 指标 | 含义 |
|------|------|
| `F1` | 精确率与召回率的调和平均，异常检测主指标 |
| `Precision` | 预测为异常的样本中，真实异常的比例 |
| `Recall` | 所有真实异常样本中，被正确检出的比例 |
| `Accuracy` | 总体分类正确率 |
| `AUC-ROC` | ROC 曲线下面积，衡量整体区分能力 |
| `AP` | Average Precision，PR 曲线相关指标 |
| `AC@1/3/5` | 根因是否出现在 Top-1 / Top-3 / Top-5 |
| `Avg@5` | 根因排序综合质量指标 |
| `miss@100ms` | 响应时间超过 `100ms` deadline 的比例 |
| `mean / p95 / p99 / max` | 平均值 / 95 分位 / 99 分位 / 最大延迟 |
| `peak memory` | 峰值显存占用 |

## 论文问题

1. **论文方法创新性不够**
   - 审稿人认为这篇工作更像是把已有模块拼起来做工程整合，而不是提出了清晰的新方法。
   - 比如用了 Sentence-BERT、投影编码器、Transformer 融合、任务头等，但“真正新在哪里”说服力不够。
2. **多模态的必要性没有被证明**
   - 消融实验里，去掉文本模态后，F1 只从 0.9584 降到 0.9565，说明文本贡献很小。
   - 但去掉时序模态后，性能大幅下降到 0.3408，说明效果几乎主要靠时序数据。
3. **对比实验不够强**
   - 资源预测部分主要只和 LSTM 比，缺少更强的多模态/多任务回归基线。
   - 审稿人认为这样不足以支撑“统一框架明显更优”的结论。
4. **泛化性不足**
   - 实验只在 **Alibaba GPU Cluster Trace** 这个数据集上做。
   - 没有跨数据集、跨环境验证，所以很难证明方法具有广泛适用性。
5. **结论表述偏强**
   - 审稿人认为目前最多只能说明“在这个特定数据集上有效”，还不足以支持更强的一般性结论。

- **Reviewer #1 相对更正面**，也有意义，建议补充统计显著性分析。
- **Associate Editor、Reviewer #2、Reviewer #3 总体都偏否定**
