# 实验与结果总表

## 指标说明

| 指标 | 含义 |
|------|------|
| `F1` | 精确率与召回率的调和平均，异常检测主指标 |
| `Precision` | 预测为异常的样本中，真实异常的比例 |
| `Recall` | 所有真实异常样本中，被正确检出的比例 |
| `Accuracy` | 总体分类正确率 |
| `AC@1/3/5` | 根因是否出现在 Top-1 / Top-3 / Top-5 |
| `Avg@5` | 根因排序综合质量指标 |
| `miss@100ms` | 响应时间超过 `100ms` deadline 的比例 |
| `mean / p99 / max` | 平均值 / 99 分位 / 最大延迟 |

### 2.1 原始版 vs 新版 Realtime 对比

| 版本 | 数据集 | 场景 | mean response | p95 | p99 | max | miss@100ms | peak memory |
|------|--------|------|--------------:|----:|----:|----:|-----------:|------------:|
| `V6 raw (6-layer)` | `MSDS` | paced replay | 24.28 ms | 32.18 ms | 37.07 ms | 311.56 ms | 0.2% | 338.17 MB |
| `V6 optimized (6-layer)` | `MSDS` | paced replay | 23.09 ms | 34.49 ms | 58.34 ms | 100.13 ms | 0.4% | 338.36 MB |
| `V6-3layer raw` | `MSDS` | paced replay | 26.88 ms | 34.72 ms | 40.29 ms | 161.95 ms | 0.2% | 251.80 MB |
| `V6 current reference (6-layer)` | `RE2-TT` | paced replay | 74.58 ms | 112.05 ms | 189.19 ms | 201.56 ms | 14.0% | 395.23 MB |
| `V6-3layer raw` | `RE2-TT` | paced replay | 73.97 ms | 101.33 ms | 115.07 ms | 124.01 ms | 6.0% | 297.27 MB |

结论：
- `MSDS` 上最原始 `6-layer raw` 已经能做到较低 `miss@100ms`，但极端尾延迟很差，`max=311.56ms`。
- `V6-3layer raw` 的主要收益不是平均响应更快，而是显存更低、最坏情况更稳。
- `RE2-TT` 上 `3layer raw` 的收益更明显，`miss@100ms` 从 `14.0%` 降到 `6.0%`，`p99/max` 也显著下降。

### 2.2 `6-layer raw` vs `3layer raw` vs `MoE-adapter-light`

说明：这里的 `MoE-adapter-light` 采用当前已收口的代表点，而不是所有 MoE 配置的平均表现。
- `MSDS` 使用 follow-up 后的最佳“真 MoE”配置：`e4/topk2/bal0.05/temp0.7`
- `RE2-TT` 使用当前 sweet spot：`epoch_01`

| 版本 | 数据集 | 场景 | mean response | p95 | p99 | max | miss@100ms | peak memory | 当前判断 |
|------|--------|------|--------------:|----:|----:|----:|-----------:|------------:|----------|
| `V6 raw (6-layer)` | `MSDS` | paced replay | 24.28 ms | 32.18 ms | 37.07 ms | 311.56 ms | 0.2% | 338.17 MB | 原始参考，极端尾延迟差 |
| `V6-3layer raw` | `MSDS` | paced replay | 26.88 ms | 34.72 ms | **40.29 ms** | 161.95 ms | 0.2% | **251.80 MB** | 当前 realtime 主线 |
| `MoE-adapter-light (best true MoE)` | `MSDS` | paced replay | 39.42 ms | 51.47 ms | 60.64 ms | **73.20 ms** | **0.0%** | 255.86 MB | 零 miss、max 最稳，但整体尾部仍慢于主线 |
| `Service-aware MoE (stage-2)` | `MSDS` | paced replay (`1000ms/1000ms`) | 30.57 ms | 40.04 ms | 47.05 ms | 103.95 ms | 0.0% | 250.96 MB | 第二阶段 MoE 在 `MSDS` 上也已闭环，但口径是 `1000ms` deadline |
| `V6 current reference (6-layer)` | `RE2-TT` | paced replay | 74.58 ms | 112.05 ms | 189.19 ms | 201.56 ms | 14.0% | 395.23 MB | 旧主线参考 |
| `V6-3layer raw` | `RE2-TT` | paced replay | 73.97 ms | 101.33 ms | 115.07 ms | 124.01 ms | 6.0% | 297.27 MB | 当前 deployment 主线 |
| `MoE-adapter-light (sweet spot)` | `RE2-TT` | paced replay | 67.26 ms | **84.28 ms** | **88.25 ms** | **97.35 ms** | **0.0%** | **295.27 MB** | tradeoff 很亮眼，但仍缺主线级稳定性验证 |
| `Service-aware MoE (stage-2)` | `RE2-TT` | paced replay | **28.95 ms** | **36.99 ms** | **42.83 ms** | **44.08 ms** | **0.0%** | 295.28 MB | 当前最强 `RE2-TT` service-aware 结果，但仍需多 seed / MSDS 迁移确认 |

结论：
- `MSDS` 上，`MoE` 的亮点是把 `miss@100ms` 压到 `0.0%`，并把 `max` 压到 `73.20 ms`；但 `mean/p95/p99` 仍然不如 `V6-3layer raw`。
- `RE2-TT` 上，当前 sweet spot `MoE` 的 realtime 指标实际上优于 `V6-3layer raw`
- 新的 `service-aware MoE (stage-2)` 在 `RE2-TT` 上进一步把 `mean/p95/p99/max` 全部压低到当前最好，但它还缺 `multi-seed` 和 `MSDS` 对照，因此暂时仍归为高潜力 MoE 支线
- `service-aware MoE (stage-2)` 现在已经补齐了 `MSDS`，说明这条线不是只在 `RE2-TT` 上偶然成立；下一步真正缺的是 `multi-seed`
- `RE2-TT seed=7` 说明这条线的离线 `F1` 仍有一定波动，但 replay 指标依旧保持 `0% miss`，所以当前更像“实时性稳定、离线效果仍需多 seed 统计”的方案
- `MSDS seed=7` 与 `seed=42` 的 offline / replay 都较接近，说明这条线在 `MSDS` 上的稳定性明显更好

### 2.3 `RTSS-MoE P0` 的 P0.1 小修正

| 版本 | 数据集 | 场景 | mean response | p95 | p99 | max | miss@100ms | 结论 |
|------|--------|------|--------------:|----:|----:|----:|-----------:|------|

| `RTSS-MoE P0.1` | `MSDS` | paced replay, `prefetch` | 45.53 ms | 66.92 ms | 92.20 ms | 162.22 ms | 0.8% | 单开 prefetch 已显著改善 |
| `RTSS-MoE P0.1` | `MSDS` | paced replay, `prefetch+pin` | 40.71 ms | 49.65 ms | 56.89 ms | 134.62 ms | 0.2% | 当前最优 P0.1 运行配置 |
| `RTSS-MoE P0` | `RE2-TT` | paced replay, `prefetch+pin` | 58.82 ms | 208.05 ms | 257.31 ms | 268.75 ms | 10.0% | `RE2-TT` 上当前不成立 |

补充：
- `MSDS P0` 的 offline 结果是 `F1=0.9242, P=0.8649, R=0.9922, Acc=0.9987`。
- 路由 diagnostics 修正后，当前 `MSDS test` 的 `route_switch_rate=0.0061`，说明 router 不是完全静态，只是切换很少。
- 这组结果说明：当前 `RTSS-MoE` 的首要瓶颈不是 expert 计算，而是 runtime 数据供给；因此下一步应该先带着 `prefetch+pin` 进入 `RE2-TT`，而不是立刻做大范围 `top-1/top-2` 扫描。
- `RE2-TT P0` 的 offline 结果是 `F1=0.8939, P=0.9129, R=0.8757, Acc=0.9985`；routing diagnostics 为 `effective_experts=2.980`, `route_switch_rate=0.0383`。
- 但它的 replay 结果仍明显差于现有 `RE2-TT MoE sweet spot` 与 `V6-3layer raw`，因此当前更适合视为“P0 未过停机线”的结果。
